# Space Flight AI — Fine-tuning Pipeline

Training an LLM to understand orbital mechanics and make reasoned rocket flight decisions.

## Project Overview

This pipeline fine-tunes Qwen2.5-7B-Instruct on NASA technical reports, orbital mechanics textbooks, and flight transcripts so the model can:
- Understand orbital mechanics deeply (Hohmann transfers, gravity turns, delta-v)
- Make structured flight decisions with full chain-of-thought reasoning
- Reference specific aerospace theory in its decision logs
- Serve as the reasoning backbone for a PPO-based RL flight agent (Phase 2)

## Server Setup — Step by Step

### 1. Clone the Repository
```bash
git clone https://github.com/YOUR_USERNAME/space-flight-ai.git
cd space-flight-ai
```

### 2. Create Environment File
```bash
cp .env.example .env
```
Edit `.env` and fill in:
```
HF_TOKEN=your_huggingface_token_here
OPENAI_API_KEY=your_openai_key_here
WANDB_API_KEY=your_wandb_key_here   # optional but recommended
```

Get your HuggingFace token at: https://huggingface.co/settings/tokens
Get your OpenAI key at: https://platform.openai.com/api-keys

### 3. Install Dependencies
```bash
pip install -r requirements.txt
```

### 4. Verify GPU Access
```bash
python3 -c "import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0))"
```
Expected output:
```
True
NVIDIA H100 80GB HBM3
```

### 5. Launch Jupyter
```bash
jupyter notebook --ip=0.0.0.0 --port=8888 --no-browser
```
Then open the URL shown in the terminal on your local machine.

## Running the Pipeline

### Notebook 01 — PDF Ingestion
**Purpose:** Parse all PDFs → generate structured training pairs via GPT-4o

1. Open `01_pdf_ingestion_pipeline.ipynb`
2. Confirm PDFs are in the `./pdfs/` folder
3. Run all cells top to bottom
4. Expected outputs:
   - `parsed_docs.json` — raw markdown from all PDFs
   - `training_pairs.jsonl` — structured decision+reasoning pairs
   - `finetune_ready.jsonl` — formatted for QLoRA fine-tuning
5. Expected runtime: 30-60 minutes depending on number of PDFs

### Notebook 02 — Fine-tuning
**Purpose:** Fine-tune Qwen2.5-7B-Instruct on the generated training pairs

1. Open `02_finetune_qwen.ipynb`
2. Confirm `finetune_ready.jsonl` exists (generated by notebook 01)
3. Run all cells top to bottom
4. Expected outputs:
   - `checkpoints/` — saved after each epoch
   - `space_flight_ai_model/` — final LoRA adapter weights
   - `space_flight_ai_model/training_config.json` — training log
5. Expected runtime on H100: **4-8 hours**

## What Gets Saved

| File | Size | Description |
|---|---|---|
| `space_flight_ai_model/adapter_model.safetensors` | ~120MB | LoRA weights only |
| `space_flight_ai_model/adapter_config.json` | tiny | LoRA configuration |
| `space_flight_ai_model/tokenizer*` | ~5MB | Custom tokenizer with special tokens |
| `checkpoints/checkpoint-*/` | ~300MB each | Per-epoch saves |

> Note: Full base model (Qwen2.5-7B) is ~15GB and downloaded from HuggingFace automatically. It is NOT stored in this repo.

## Troubleshooting

**CUDA out of memory:**
Reduce `BATCH_SIZE` from 8 to 4 in notebook 02, Step 1 config.

**Model download fails:**
Check HF_TOKEN is set correctly. Verify internet access on the server.

**PDF parsing fails:**
Check Docling version: `pip show docling` — must be ≥ 2.0.0

**Training loss not decreasing:**
Dataset may be too small. Add more PDFs and rerun notebook 01. Aim for 2000+ training pairs.
